# East Fu Lean APS

東福精實生產排程系統是一個簡潔、中文介面、Excel 驅動的 Lean APS MVP。

## 啟動方式

```bash
pip install -r requirements.txt
python scripts_make_demo.py
python -m streamlit run app.py
```

若要部署給公司同仁連線使用，請見 [DEPLOYMENT.md](DEPLOYMENT.md)。
若要部署成公開網址，請見 [STREAMLIT_CLOUD_DEPLOY.md](STREAMLIT_CLOUD_DEPLOY.md)。

內建標準資料 Excel 路徑：

```text
data/EastFu_Lean_APS_Demo.xlsx
```

## 使用流程

上傳 Excel，或按「載入東福標準排程資料」，完成驗證後選擇策略並執行 APS 排程。系統會產生排程結果、Plotly 甘特圖、KPI、策略比較與推薦方案，並可匯出 Excel 與甘特圖 HTML。

日常主流程控制在六步：

1. 上傳訂單 Excel
2. 設定排程開始與排程期間
3. 選擇排程策略與本次使用機台
4. 確認工時模式、人力比例與基本設定
5. 按「確認設定並開始排程」
6. 查看甘特圖與 KPI

## Excel 工作表

- 待排工單
- 產品機台產速
- 機台初始狀態
- 換模時間
- 填表說明

`機台可用時間` 與 `排程基本設定` 為相容舊檔案的選填工作表。新範本不再需要這兩張表；系統預設 C2/C4/C5 在排程期間都可用，排程開始、排程期間、工時模式、週末與指定休假日都在畫面中設定。

範本中必要欄位的欄名會以紅色系底色標示，`填表說明` 工作表也會列出每個欄位的定義、必填狀態、範例與備註。必要工作表只有 `待排工單` 與 `產品機台產速`；`機台初始狀態` 是進階選填，空白時系統視為空機台，第一張工單不計換模；`換模時間` 可依現場資料填寫。每張工單若要限制只能使用特定機台，請在 `待排工單` 的 `工單限定機台` 填入 `C4` 或 `C4,C5`；空白代表依產品機台產速表判斷。舊檔的 `允許機台`、`限定機台`、`可排機台` 等欄名仍可相容讀取。

`產品機台產速` 是產品層級的基本能力，例如同一產品分別有 C2、C4 兩列，各自填不同產速。`工單限定機台` 是工單層級的例外限制，只有該張工單受到限制。

`交期` 若只填日期，例如 `2026/09/05`，系統會視為當天結束前交貨，也就是 `2026/09/05 23:59:59`。若需要更精準交期，請直接填日期加時間，例如 `2026/09/05 15:30`。

## 工時模式

排程開始時間直接在畫面設定。選擇 `24 小時`、`48 小時`、`72 小時` 或 `一週` 時，系統會從畫面上的排程開始時間往後計算。

在畫面 `基本設定` 中選擇工時模式：

- `24 小時連續排程`：排程期間內連續可排，除非遇到週末、指定休假日或特殊狀況 / 停機。
- `每日 8 小時排程`：依每日開始時間與每日可排工時自動產生不可排程時段。預設每日 08:00 起算 8 小時。

每日 8 小時模式下，工單仍維持不拆分、不跨不可用時段。若單張工單加工時間超過單日可用工時，系統會標示為無法排入。

### 本次使用機台與人力

畫面上可勾選本次排程使用的機台，例如只勾 `C4`、`C5`，系統就不會把工單排到 `C2`。若某產品沒有任何被勾選機台的產速資料，該工單會無法排入並在結果中提示。

若當天有人請假或人力不足，可在 `基本設定` 選擇 `正常產能（100%）`、`人力不足（80%）`、`嚴重不足（60%）` 或 `自訂`。系統會依比例折減產速後排程，讓預估時間偏向現場可達成的結果；這是簡單的整體產能折減，不需要先建立人員主檔。

## 操作問題小幫手

畫面提供 `操作問題小幫手` 與 `內建使用手冊`。此版本使用內建手冊內容回答，不連接外部 AI API，適合公開部署與初期試用。完整手冊也整理在 [USER_MANUAL.md](USER_MANUAL.md)。

## 換模時間設定

在 `產品機台產速` 中維護每個產品的 `換模群組`。同一產品若可在多台機台生產，請依產品與機台拆成多列，並分別填產速與換模群組。

在 `換模時間` 中維護群組對群組的換模分鐘數：

| 來源換模群組 | 目標換模群組 | 換模時間_分鐘 |
|---|---|---:|
| G1 | G2 | 30 |
| G2 | G1 | 45 |

排程規則：

1. 同一換模群組接續生產，換模時間為 0。
2. 若 `換模時間` 有設定來源與目標群組，就使用該分鐘數。
3. 若沒有設定，就使用畫面上的 `預設換模時間（分鐘）`。

## 支援策略

- 急單優先＋最早交期
- 最早交期優先
- 先進先出
- 最短加工時間優先
- 最短等待時間優先
- 機台負載平衡
- 東福 Lean 綜合排程
- 減少換模

## 第二版新增

- 欄位 alias normalization：支援工單編號 / WO / work_order、產品編號 / Product、需求日期 / Due Date、Quantity、Priority 等欄名。
- Friendly validation：缺欄位時顯示中文訊息與偵測到的欄位，不暴露 KeyError 或 traceback。
- Planning horizon：支援 24 小時、48 小時、72 小時、一週、自訂開始 / 結束。
- 排程基本設定畫面化：新 Excel 範本不需 `排程基本設定` 工作表，舊檔仍可讀取並作為畫面預設值。
- 工時模式：支援 24 小時連續排程與每日 8 小時排程。
- Changeover：支援群組對群組換模時間表，未設定時使用預設換模時間，會影響開始時間、makespan、tardiness、換模次數。
- 操作問題小幫手：內建常見問題回答，不需 API key。
- 特殊狀況 / 停機：機台保養、臨時停機、盤點等期間不可排入生產，可一鍵清除已輸入的特殊狀況。
- 急單：可新增急單並建立新 schedule version。
- 歷史排程：每次排程保存到 `data/schedule_history.json`，重啟後仍可查看版本、訂單、甘特圖與 KPI。

## KPI 公式

- 完成工單數：結束時間未超過排程 horizon 的工單數。
- 未完成 / 超出 horizon 工單數：結束時間超過排程 horizon 的工單數。
- 準時完成率：未遲交工單數 / 總工單數 * 100。
- 遲交工單數：結束時間晚於交期的工單數。
- 總遲交時間：所有工單 max(結束時間 - 交期, 0) 的小時數總和。
- 平均遲交時間：總遲交時間 / 總工單數。
- 最大遲交時間：單張工單最大遲交小時數。
- Makespan：最後完工時間 - 排程開始時間。
- 平均等待時間：總等待時間 / 總工單數。
- 總等待時間：所有工單 max(開始時間 - 排程開始時間, 0) 的總和。
- C2/C4/C5 utilization：該機台加工時間 / horizon 小時數 * 100。
- 平均 utilization：三台機台 utilization 平均。
- Resource Load Imbalance：最大機台 utilization - 最小機台 utilization。

## 推薦邏輯

系統使用透明規則排序，不宣稱 AI 最佳化：

1. 準時完成率越高越好。
2. 總遲交時間越低越好。
3. 平均等待時間越低越好。
4. 資源負載不均越低越好。
5. Makespan 越低越好。

## 第一版限制

- 工單不拆分。
- 一張工單只排在一台合格機台。
- 工單開始後不插單、不中斷。
- 排程演算法為 deterministic heuristic。
- 手動調整為簡單下拉式機台指定，不支援拖拉甘特圖。
